## 0️⃣ 开场：题目与结题形式（约 25 秒）

各位老师好。我的题目是**《AI 辅助下行为树解释器的形式语义建模与 SMT 验证》**，
拟采用**工程实践 · B 自命题**的形式结题：交付一个**可运行的开源 Demo**——
用 Python 实现行为树解释器，把它建模成有限状态机，用 z3 求解器做自动验证，
代码放到 GitHub 上，并结合云端算力做规模实验，争取拿到"开源链接 + 云端算力"的提档。

## 1️⃣ 我做的是什么（约 70 秒）

选这个题是因为一个真实痛点：行为树在游戏和机器人里用得非常多，但它的语义细节——
比如节点返回 RUNNING 时谁记住什么、并行节点怎么算成功——**各家引擎规定得不一样**，
同一棵树换个引擎就可能出 bug。所以我想给它的执行语义一套**严格的数学定义**，并且让机器能自动检查。

整个流水线分四步，全部可以跑：

1. **形式化**：用结构操作语义（SOS）把每个节点的 Tick 规则写成"前提—结论"的推理规则，一共 14 条；
2. **可执行**：把这 14 条规则逐条实现成 Python 解释器，规则和代码一一对应；
3. **建模**：探索整棵树的状态空间，抽取成有限状态机——状态就是节点的记忆，输入是环境，输出是动作事件；
4. **验证**：把"看见敌人必须 2 拍内开始逃跑"这类性质写成时序逻辑，交给 z3 做有界模型检测。

举个实际结果：我故意构造了一个 bug——把"低血量才治疗"的条件用取反装饰器**写反了**，
结果治疗分支永远成功、永远抢占，**逃跑动作永远执行不到**。
z3 在 0.006 秒内自动给出了反例轨迹，精确指出从第 0 拍起敌人持续可见但逃跑始终没有触发。
这就是形式化方法的价值：**bug 不用靠玩家踩坑，机器直接证明给你看**。

## 2️⃣ AI 帮我干了什么（约 60 秒）

这个项目是典型的"AI 写初稿、人做判断"的协作，我把它分成三层，也是诚实的边界：

**AI 生成的**：SOS 规则的 LaTeX 排版初稿、z3 的编码框架、测试用例骨架和 README。
这部分大概占代码量的一半，速度上是数量级的提升。

**我决策的**：所有语义设计——比如"节点终止必须清空记忆"这条不变量、
并行节点"失败优先于成功"的判定、以及性质里"sustain"参数的引入。
这些决定了整个系统对不对，AI 给的是选项，选择和论证是我做的。

**我纠错的**：AI 生成的 z3 编码有**两个真实的 bug**——一是忘了把初始状态钉死，
导致求解器从任意状态起跑，反例全是假的；二是性质窗口在 horizon 末尾被截断，产生误报。
这两个问题都是我靠"把反例**回放到解释器上重新执行**"这套交叉复核机制发现并修掉的——
现在每一次验证输出里都有"回放复核：通过"这一栏。

一句话总结：**AI 负责写得快，我负责判断对不对**——而"判断"这件事本身，
恰恰是靠这套形式语义才能自动化的。

## 3️⃣ 收尾：算力规划（约 25 秒）

最后是算力需求，我有实测数据：并行分支从 4 个加到 6 个，状态空间从 768 条边涨到 7.7 万条，
BMC 编码直接超出单机预算；按公式外推到 10 个分支就是 1.7 亿条边、约 17 GB 显式存储——
**单机不可行，必须上云端做分布式探索**，这也是我下一阶段的重点工作。

以上就是我的题目、做法和 AI 协作方式，谢谢老师，欢迎提问。

## 附：预计被问的三个问题（一句话答案）

| 可能的问题 | 一句话回答 |
|---|---|
| unsat 只是"K 步内没反例"，不算完全证明吧？ | 对，所以报告里明确写"有界结论"；完全证明需要 k-induction，列为未来工作 |
| 为什么用 z3 不用 NuSMV？ | z3 是 SMT 求解器，方便把动作时长当整数编码；NuSMV 原生支持 LTL/BDD，规模更大时更适合，二者可在同一 FSM 上交叉验证 |
| 状态爆炸了怎么办？ | 三条路：缩小环境抽象、换符号化表示（BDD）、按顶层子树切块多机并行——这正是云端算力的用武之地 |
